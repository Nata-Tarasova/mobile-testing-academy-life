# 📄 Баг-репорт BR_2: Критическая задержка воспроизведения видеоролика на мобильном 3G/4G интернете

### 📝 Описание дефекта
Отсутствие мобильной оптимизации видеофайла `newvideo2.mp4` на стороне веб-сервера. Это приводит к критическим задержкам загрузки, бесконечной буферизации и рывкам при попытке воспроизведения через мобильное соединение (наблюдается избыточный объем данных при HTTP-запросах со статусом 206).

### 🛠️ Окружение (Environment)
* **Симуляция девайса:** Смартфон Poco X7 Pro (разрешение 412x915px, DPR 3.5)
* **Браузер:** Google Chrome 151.0.7922.174 DevTools
* **ОС:** Windows 11

### 📋 Предусловия (Pre-conditions)
1. Открыта панель инструментов разработчика Google Chrome DevTools.
2. Включена эмуляция смартфона Poco X7 Pro.
3. Выполнен переход на тестируемый стенд: `https://academy-of-life.ru`

### 👣 Шаги воспроизведения (Steps to Reproduce)
1. В DevTools на вкладке **Network (Сеть)** ограничить скорость профилем **«4G»**.
2. Включить фильтр типов контента **Media**.
3. Проскроллить страницу фонда вниз до видеоплеера.
4. Нажать кнопку воспроизведения (Play) на плеере.
5. Оценить время загрузки и плавность потока для файла `newvideo2.mp4`.

### 🎯 Ожидаемый результат (Expected Result)
Видеоролик оптимизирован для мобильных платформ. Общий размер файла не превышает 10–15 МБ. Стартовый пакет данных (chunk) загружается за 1.5–2 секунды, обеспечивая непрерывное воспроизведение потока без фризов, зависаний и постоянной буферизации.

### ❌ Фактический результат (Actual Result)
Видео воспроизводится рывками, трансляция регулярно прерывается экраном загрузки. Вкладка *Network* фиксирует, что частичные пакеты (Status 206) видеофайла `newvideo2.mp4` имеют избыточный вес (18.3 МБ на пакет) и скачиваются критически долго (около 1.2 минут). Плеер не успевает наполнять буфер обмена.

### 💡 Комментарий для разработки (Technical Notes)
На бэкенд загружен медиафайл без предварительного сжатия и подготовки под мобильный веб-трафик (избыточный битрейт, неоптимальный кодек или завышенное разрешение). Сервер перегружается, пытаясь отдать тяжелый массив данных.
**Рекомендации инженера:**
1. Сжать видеофайл с помощью FFmpeg/HandBrake, уменьшив разрешение под мобильные экраны и оптимизировав битрейт.
2. Использовать современные веб-контейнеры или кодеки (например, H.264/H.265 с флагом `faststart` для быстрого старта воспроизведения до полной загрузки файла).
